# ADR-0042: Token exchange authentication (v4)

**Status:** Active. Supersedes ADR-0031.

## Context

ADR-0031 made `auth-svc` a synchronous dependency of every authenticated request and
locked identity to browser cookies. We needed mobile clients, partner integrations and a
service that could tolerate `auth-svc` being briefly unavailable.

## Decision

Identity is now carried by a short-lived signed token instead of an opaque session id.

1. The client authenticates once and receives a refresh token bound to a device id.
2. Before calling a service, the client exchanges the refresh token for a 5-minute
   access token at `POST /v4/token`. The access token is an EdDSA-signed JWT.
3. Downstream services verify the signature locally against the published JWKS. There
   is no introspection call and no network hop on the hot path.

The JWKS document is served from `GET /v4/.well-known/jwks.json` and cached in-process
for 10 minutes by every consumer.

## Consequences

Verification is local, so `auth-svc` is no longer on the critical path of every request.
Its availability now only caps *login and token exchange*, not all traffic.

Revocation is no longer immediate. A stolen access token stays valid for up to five
minutes. We accepted this: the alternative was keeping the synchronous introspect call.
Refresh tokens are revocable immediately and are checked on every exchange.

The token exchange itself is a new outbound call that clients did not previously make.
Services that call `auth-svc` on behalf of a user — rather than passing a token through —
now make one extra outbound HTTPS request per token lifetime. Teams migrating to v4 must
size their outbound connection pools for this. ADR-0061 covers what happens when they do
not.

## Migration

Consumers migrate service by service. Both flows run in parallel until the last v3
consumer is gone; see the platform deprecation policy for the current list.
